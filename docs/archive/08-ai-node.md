# 08 · AI node

An AI node asks a model for a structured answer as one step of a decision. It is the only node allowed to wait on the network, and it always has a way out.

## 1. How the call is made

The sidecar makes **one HTTP call to the Integration Hub** per AI node invocation. The Hub owns provider keys, model routing and quotas; Gearbox only holds a Hub credential (`GEARBOX_HUB_TOKEN_FILE`).

> The Hub's real contract was not available when this was written. [`openapi/integration-hub-ai.yaml`](openapi/integration-hub-ai.yaml) is a placeholder. When the Hub team shares their spec, replace the placeholder and adjust `sidecar/internal/hub` only; the AI node definition below does not change.

Placeholder call:

```
POST {GEARBOX_HUB_URL}/v1/ai/completions
Authorization: Bearer <hub token>
Idempotency-Key: <call_id>          # generated by the sidecar per AI call; never the caller's request_id
{
  "model": "reasoning-default",
  "messages": [ {"role": "system", "content": "..."}, {"role": "user", "content": "..."} ],
  "response_schema": { ...JSON Schema... },
  "max_output_tokens": 300,
  "temperature": 0,
  "timeout_ms": 1400,                 # node timeout minus a safety margin
  "metadata": { "decision": "lead_routing@v17", "node": "priority", "request_id": "...", "call_id": "..." }
}
→ 200 { "output": { ...matches response_schema... }, "model": "provider-model-2026-09", "usage": { "input_tokens": 512, "output_tokens": 40 } }
```

## 2. Node definition

```yaml
- id: priority
  type: ai
  ai:
    model: reasoning-default            # alias resolved by the Hub
    mode: shadow                        # shadow | inline | precompute
    timeout: 1500ms
    vars:                               # the only values the prompt may use (allow-list)
      car:     input.car.make + " " + input.car.model + ", " + string(input.car.year) + ", " + string(input.car.km) + " km"
      avg:     nodes.normalize.inspection.avg
      weak:    nodes.normalize.inspection.weak
      city:    input.lead.city
    prompt:
      system: |
        You rate follow-up priority for used-car leads. Answer only with the JSON schema.
      user: |
        Car: {{ car }}. Inspection average: {{ avg }}. Weak parts: {{ weak }}. City: {{ city }}.
    output_schema:
      type: object
      required: [route, reason]
      properties:
        route:  { enum: [fast_track, standard, manual_review] }
        reason: { type: string, maxLength: 200 }
    cache: { ttl: 6h, max_entries: 50000 }   # key = hash(rendered prompt, model alias, schema)
    budget: { max_calls_per_minute: 600, max_output_tokens: 300 }   # for the whole app and environment, not per pod
  onError: default_priority
```

`vars` are Expr expressions compiled at publish; `{{ name }}` inserts a var as JSON text. The prompt cannot reference `input` or `nodes` directly, so every value that reaches the model is listed in one place for review.

## 3. Modes

| Mode | Who decides | Latency added to the caller | Use for |
|---|---|---|---|
| `shadow` | The `onError` path (rules) always decides; the AI call runs in the background and its answer is logged next to the rules' answer | none | Every new AI node, until the agreement report says it is good |
| `inline` | The AI answer, if it arrives within `timeout` and matches the schema; otherwise `onError` | up to `timeout` | Decisions where a few hundred ms is acceptable |
| `precompute` | An event or batch job calls the decision ahead of time and stores answers in a lookup table; requests read the lookup | none at request time | High-volume decisions where answers can be computed earlier |

## 4. Guarantees

- A timeout, Hub error, rate-limit, or an answer that fails `output_schema` always routes to `onError`; the response has `fallback_used=true` and the path shows `outcome: fallback`.
- PII never reaches the prompt. Fields marked `x-gearbox-pii` in the input schema, and every value derived from them through transforms or expressions, are tracked by the compiler; a `var` that depends on one is a publish error.
- The cache key is the hash of the rendered prompt, model alias and schema, so a cached answer is only reused for exactly the same question.
- Model alias, prompt and schema are part of the decision version. Changing any of them is a new version that goes through review.
- Calls are logged with decision version, node, the concrete model the Hub reports, latency, token usage, cache hit and a hash of the answer; prompts and answers are logged only when the decision's `logging.ai_payloads` is on (off by default).
- **Not reproducible.** The Hub can change the model behind an alias, and caches are per pod, so AI answers are excluded from the replay guarantee. The logged model and answer hash make them auditable.
- **Budget is global.** The calls-per-minute budget is shared by every sidecar of the app and environment: each sidecar takes a share proportional to its traffic from the control plane, and the Hub enforces the hard limit.
- Circuit breaker per Hub endpoint (`sony/gobreaker`): after repeated failures, AI nodes go straight to `onError` for 30 s.

## 5. Shadow report

For shadow nodes the UI shows, per decision version: calls, agreement rate with the deciding path, disagreements with the prompt vars (PII-free by construction), Hub latency p50/p95 and cost estimate. Switch a node to `inline` only from this screen, as a new version.

## 6. Tools (later)

v1 nodes are single prompt → schema answers. Tool use (letting the model call lookups, other decisions or service endpoints) is planned for v2 once the Hub contract supports it.
